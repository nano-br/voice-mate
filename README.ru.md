# VoiceMate

> Нажмите горячую клавишу, скажите, вставьте. Локальная расшифровка Whisper прямо в буфер обмена, или через Claude с ответом, который зачитывается вам вашим собственным голосом.

## Зачем

Облачная диктовка работает быстро, пока не перестаёт. VoiceMate запускает Whisper **локально** на вашей GPU: звук не покидает ваш компьютер, нет сетевых задержек, абонентской платы и компромиссов с приватностью. Нажмите горячую клавишу, говорите, вставляйте куда угодно.

## Возможности

- **Горячая клавиша-переключатель**: нажмите один раз, чтобы начать запись, и ещё раз, чтобы остановить и расшифровать
- **Два режима, один микрофон**: `Ctrl+Alt+V` кладёт расшифровку в буфер обмена; `Ctrl+Alt+A` отправляет её Claude (многоходовой диалог) и зачитывает ответ ИИ через TTS
- **Локальная расшифровка**: `faster-whisper` (CTranslate2) на NVIDIA/CPU или `whisper.cpp` + Vulkan на GPU AMD (~1.6 ГБ видеопамяти, large-v3-turbo); бэкенд выбирается автоматически под вашу GPU
- **Ускорение на GPU любого производителя**: поддерживаются и NVIDIA (CUDA), **и** AMD (Vulkan + ROCm), с автоматическим переходом на CPU. В простое видеопамять почти не занята (STT работает в подпроцессе, TTS загружается при первой реплике)
- **Сменный TTS**: ответ Claude зачитывает [VoxCPM2](https://github.com/OpenBMB/VoxCPM) (2B параметров, голос по текстовому описанию, потоковый вывод). Каждый движок TTS изолирован в архитектуре, поэтому его можно заменить или убрать, не трогая остальное
- **Двойной буфер обмена с Win+V**: режим ИИ сначала копирует расшифровку, затем ответ, и журнал буфера обмена Windows показывает их рядом для проверки
- **Остановка решает, куда пойдёт текст**: начните любой горячей клавишей; клавиша, которой вы *останавливаете* запись, выбирает обработчик (буфер обмена или Claude)
- **Отмена на лету**: нажатие любой горячей клавиши, пока Claude отвечает (или пока говорит TTS), мгновенно всё отменяет и начинает новую запись, сохраняя диалог
- **Самовосстанавливающийся слушатель**: периодически переустанавливает глобальную горячую клавишу, если Windows молча снимает перехватчик под нагрузкой
- **Сторожевой таймер**: следит за состоянием процесса и автоматически перезапускает его при зависании
- **Настраиваемая максимальная длительность записи**: защищает от забытых сеансов (по умолчанию 10 минут)
- **Звуковые сигналы**: разные сигналы для начала записи, предупреждения, завершения расшифровки и готового ответа ИИ
- **Запуск мышью**: при желании вместо клавиатуры можно использовать боковую кнопку мыши (только режим буфера обмена)

## Требования

- Одна из поддерживаемых сред (слой платформы сам выбирает нужные интеграции):
  - **Windows 10/11** напрямую (рекомендуется NVIDIA): исходная платформа, без изменений
  - **Linux** напрямую, X11 или Wayland
  - **WSL2** (Ubuntu) в Windows 11: приложение работает **полностью внутри WSL**, а на стороне Windows
    нужен лишь маленький скрипт горячих клавиш; рекомендуемый путь для **GPU AMD** (ROCm). См. [docs/wsl2.md](docs/wsl2.md)
- Python 3.12 (режим TTS на VoxCPM2 пока не поддерживает 3.13)
- [Poetry](https://python-poetry.org/docs/#installation)
- GPU не обязательна, но очень желательна (для TTS с приемлемой задержкой она нужна):
  - **NVIDIA** с CUDA **или**
  - **AMD** (RDNA, например RX 7000/9000) через ROCm (Linux/WSL2) или ROCm-on-Windows (Adrenalin ≥ 26.2.2)
  - Нет GPU? Всё работает и на CPU (медленнее; подумайте о `--no-tts`)
- **Только для режима Claude:** Node.js 18+ и [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) с локальным входом в аккаунт

## Установка

```bash
git clone https://github.com/nano-br/voice-mate.git
cd voice-mate
make setup
```

`make setup` **определяет вашу GPU** (NVIDIA / AMD / нет), спрашивает подтверждение, устанавливает подходящую сборку PyTorch (CUDA `cu128` для NVIDIA, ROCm для AMD или CPU) и выбранные модули, а затем запоминает всё в `~/.config/voicemate/config.toml`. Выбор можно повторить в любой момент командой **`make configure`** (например, после смены видеокарты).

> **Про AMD:** `make setup` устанавливает PyTorch с ROCm (для VoxCPM/TTS) и скачивает **whisper.cpp + Vulkan** (для расшифровки). Пакеты wheel с ROCm **не** публикуются в PyPI, а драйвер AMD Adrenalin (≥ 26.2.2) должен быть установлен заранее; если драйвер, похоже, отсутствует, установка предупредит. См. «Бэкенды GPU» ниже.

### Модульная установка (extras)

`make setup` спрашивает, какие модули вам нужны. Если хотите установить без вопросов, отдельные цели по-прежнему работают (учтите: они не ставят сборку PyTorch для GPU; после них выполните `make configure` или используйте `make setup`):

| Команда                                        | Что устанавливает                                                      |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| `make setup_env_minimal`                       | Только **ядро**: голос → расшифровка → буфер обмена.                   |
| `make setup_env_claude`                        | Ядро + `claude-agent-sdk` (включает режим Claude на `Ctrl+Alt+A`).     |
| `make setup_env_tts`                           | Ядро + `voxcpm` + `soundfile` (TTS, тяжёлый: ~5 ГБ весов модели).      |
| `make setup_env` *(устаревшая, рассчитана на NVIDIA)* | Ядро + Claude + TTS + PyTorch с CUDA (`--extras all`).          |
| `make setup_env_custom EXTRAS="claude tts"`    | Произвольный набор extras.                                             |

Extras (передаются в `poetry install --extras`): `claude`, `tts`, `whisper-gpu` (расшифровка на GPU AMD через `openai-whisper`), `all`.

Если какого-то extra нет, приложение всё равно запускается и просто отключает соответствующий режим с понятным предупреждением (`extra 'claude' не установлен`), а не падает.

### Языки

По умолчанию Claude отвечает на PT-BR. Чтобы изменить язык:

```bash
# Переключить ассистента на русский
make run ARGS="--output-lang ru"
```

Внутри канонический промпт (написанный по-английски) содержит заполнитель `{output_lang}`, который подставляется во время работы: переведённых копий промпта нет.

**Сообщения самого приложения** (журналы, справка CLI) тоже локализованы через `gettext` + Babel. По умолчанию используется PT-BR; язык меняется переменной окружения:

```bash
# Журналы приложения на русском (или `en`, `es`, `zh-CN`)
VOICEMATE_LANG=ru make run
```

Доступные каталоги: `pt_BR`, `en`, `es`, `ru` и `zh_CN`. Каждая строка, которую видит пользователь, должна быть во всех каталогах; все, кроме `en`, её переводят, а в `en` поле `msgstr` остаётся пустым (английский msgid и есть текст).

Чтобы изменить или пересобрать каталог переводов:

```bash
make i18n-extract     # извлечь строки _() в voicemate.pot
make i18n-update      # перенести новые ключи в существующие файлы .po
make i18n-compile     # скомпилировать .po → .mo (gettext загружает .mo во время работы)
```

Каталоги находятся в `app/i18n/locales/{pt_BR,en,es,ru,zh_CN}/LC_MESSAGES/voicemate.po`.

### Соглашения о коде

- **Идентификаторы, ключи конфигурации, docstring, новые комментарии**: на английском (PEP 8).
- **Промпты LLM**: канонические, на английском, с заполнителем `{output_lang}`. Никаких переведённых копий промптов.
- **Строки для пользователя** (журналы, сообщения, справка): английский как `msgid`, переводы в `app/i18n/locales/<lang>/LC_MESSAGES/voicemate.po`. По умолчанию PT-BR. Новые переводы добавляются так: пометьте строку `_()` в коде, затем `make i18n-extract && make i18n-compile`.

### Настройка Claude Code (необязательно, только для режима ИИ)

Если нужен только режим буфера обмена (`Ctrl+Alt+V`), этот раздел можно пропустить и запускать с `--no-claude-chat`.

В режиме ИИ (`Ctrl+Alt+A`) VoiceMate общается с Claude через `claude-agent-sdk`, который **использует локальный CLI `claude` и его учётные данные**: отдельный ключ API не нужен.

1. **Установите Node.js 18+** (пропустите, если он уже есть). Скачайте с [nodejs.org](https://nodejs.org/) или используйте менеджер вроде `nvm-windows` / `fnm`.

2. **Установите Claude Code глобально:**
   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

3. **Войдите в аккаунт.** Запустите CLI один раз и пройдите интерактивный вход (откроется браузер):
   ```bash
   claude
   ```
   Выберите свой способ входа (аккаунт Anthropic или Claude Pro/Max). После входа введите `/exit`, чтобы выйти из чата: учётные данные уже сохранены локально.

4. **Проверьте, что всё работает:**
   ```bash
   claude --version
   claude -p "ping"
   ```
   Если на `ping` приходит ответ Claude, всё готово.

Когда вход в Claude выполнен, режим ИИ VoiceMate подхватывает его автоматически при `poetry run voice-mate`. Если `claude` отсутствует или вы вышли из аккаунта, режим ИИ молча пропускается, а режим буфера обмена продолжает работать.

### Настройка TTS (VoxCPM2)

По умолчанию ответ Claude зачитывается с помощью [VoxCPM2](https://github.com/OpenBMB/VoxCPM): многоязычной модели на 2B параметров (с поддержкой PT-BR), которая принимает текстовое описание голоса вместо эталонной записи.

- Пакет `voxcpm` устанавливается автоматически, если ваше окружение работает на Python 3.12. При первом запуске веса модели скачиваются с Hugging Face (несколько ГБ, это займёт время).
- Голос по умолчанию: «молодая бразильянка, естественный и тёплый голос, спокойный темп»; задайте свой через `--tts-voice "..."`.
- Чтобы отключить TTS, запускайте с `--no-tts` (ответ всё равно попадёт в буфер обмена, а тройной сигнал вернётся).
- Если VoxCPM2 не удаётся запустить (нет CUDA, мало места на диске и т. п.), приложение молча переходит в режим без TTS: ничего делать не нужно.

#### Бэкенды GPU (NVIDIA / AMD / CPU)

`torch`/`torchaudio` **не** закреплены в `pyproject.toml`: нужная сборка зависит от видеокарты и ОС. `make setup` (через `app.setup.gpu_bootstrap`) определяет платформу и GPU и устанавливает правильную сборку:

| Платформа × GPU      | Сборка PyTorch             | Расшифровка (сначала лучший доступный вариант)            | TTS (OmniVoice/VoxCPM) |
| -------------------- | -------------------------- | --------------------------------------------------------- | ---------------------- |
| Windows + NVIDIA     | CUDA `cu128`               | `faster-whisper` (CUDA)                                   | GPU (CUDA)             |
| Windows + AMD        | ROCm (`repo.radeon.com`)   | **whisper.cpp + Vulkan**                                  | GPU (ROCm)             |
| Linux/WSL2 + AMD     | ROCm (pytorch.org)         | **faster-whisper через CTranslate2-ROCm** → whisper.cpp + Vulkan → openai-whisper | GPU (ROCm) |
| Linux + NVIDIA       | CUDA `cu128`               | `faster-whisper` (CUDA)                                   | GPU (CUDA)             |
| любая, без GPU       | CPU                        | `faster-whisper` (int8)                                   | CPU (медленно)         |

**AMD в Linux/WSL2 (рекомендуется для AMD):** установка предлагает собрать
[форк CTranslate2-ROCm](https://github.com/arlo-phoenix/CTranslate2-rocm); с ним расшифровка использует
тот же движок `faster-whisper`, что и на NVIDIA (качество идентично). Если пропустить сборку (или она не удастся),
цепочка автоматически переходит на **whisper.cpp**, собранный с Vulkan (серверный режим держит модель в памяти, быстрый
запуск), с silero-VAD, а затем на `openai-whisper`. Выбор запоминается (`ct2_rocm_ok` в конфигурации);
`make configure` пробует снова, `make stt-eval` объективно измеряет качество (WER + детектор разорванных слов).

**AMD в Windows:** расшифровка идёт через **whisper.cpp + Vulkan**: небольшой исполняемый файл и модель GGUF
(large-v3-turbo fp16), которые скачиваются в `~/.cache/voicemate/whispercpp/` (с проверкой SHA-256). Стек PyTorch с ROCm
всё равно устанавливается, но только для TTS.

Чтобы убедиться, что ускорение на GPU работает:

```bash
poetry run python -c "import torch; print('GPU:', torch.cuda.is_available())"
```

Команда должна вывести `GPU: True` (в ROCm HIP от AMD представляется как `cuda`, поэтому `True` верно и для AMD). Если выводится `False`:

- **NVIDIA:** обновите драйвер (`nvidia-smi`); свежие драйверы (≥ 545) поддерживают CUDA 12.8.
- **AMD:** установите или обновите драйвер Adrenalin (≥ 26.2.2), затем выполните `make configure`.

Если GPU нет и нужен только режим буфера обмена, запускайте с `--no-tts`. VoxCPMSpeaker также выводит при запуске предупреждение с учётом производителя, если обнаруживает PyTorch без ускорения.

Определение можно переопределить для отдельного запуска: `--gpu-backend {auto,nvidia,amd,cpu}`, `--whisper-backend {faster-whisper,whispercpp,openai-whisper}` и `--stt-strategy {auto,faster-whisper-rocm,whispercpp,openai-whisper}`.

### Платформы и триггеры

Слой платформы (`app/platform/`) определяет, где вы работаете, и выбирает подходящий механизм горячих клавиш и интеграцию
с буфером обмена; переопределить можно через `--platform` / `--trigger`:

| Платформа       | Триггер горячих клавиш (по умолчанию)     | Буфер обмена         | Примечания |
| --------------- | ----------------------------------------- | -------------------- | ---------- |
| `windows`       | `keyboard-hooks` (библиотеки keyboard/mouse) | pyperclip         | Поведение как раньше (включая поддержку слушателя) |
| `linux-x11`     | `pynput` (GlobalHotKeys)                  | pyperclip (xclip)    | `poetry install --extras linux` |
| `linux-wayland` | `evdev` (/dev/input, нужна группа `input`) | pyperclip (wl-copy) | `sudo usermod -aG input $USER` |
| `wsl2`          | `socket`: локальный HTTP-демон + маленький скрипт горячих клавиш на стороне Windows | синхронизация WSLg (запасной вариант `clip.exe`) | См. [docs/wsl2.md](docs/wsl2.md) |

Горячие клавиши по умолчанию везде одинаковые: `Ctrl+Alt+V` (буфер обмена) и `Ctrl+Alt+A` (Claude). В WSL2 их
регистрирует `scripts/windows/voicemate-hotkeys.ahk` (или `.ps1`), который отправляет POST-запросы демону, с той же
логикой «клавиша остановки выбирает обработчик». `make doctor` проверяет микрофон, звук, триггер и GPU и подсказывает
исправления. В Windows эти скрипты заменяет [приложение-компаньон](#приложение-компаньон-трей).

## Использование

```bash
make run
```

Горячие клавиши по умолчанию:

- **`Ctrl+Alt+V`**: режим буфера обмена (расшифровка → буфер обмена)
- **`Ctrl+Alt+A`**: режим Claude (расшифровка → Claude → ответ ИИ в буфере обмена + TTS)

### Режим буфера обмена

1. Нажмите `Ctrl+Alt+V`, чтобы начать запись (сигнал начала)
2. Говорите как обычно
3. Снова нажмите `Ctrl+Alt+V`, чтобы остановить
4. Расшифровка копируется в буфер обмена (двойной сигнал)
5. Вставьте её куда угодно через `Ctrl+V`

### Режим Claude (многоходовой диалог голосом)

1. Нажмите `Ctrl+Alt+A`, чтобы начать запись
2. Произнесите свой запрос
3. Снова нажмите `Ctrl+Alt+A`, чтобы остановить: VoiceMate расшифрует запись, скопирует расшифровку в буфер обмена и отправит её Claude
4. Ответ ИИ заменяет содержимое буфера обмена, и VoxCPM2 начинает зачитывать его (по умолчанию на PT-BR)
5. Снова нажмите `Ctrl+Alt+A`, чтобы задать уточняющий вопрос: диалог продолжается в том же сеансе

**Остановка решает, куда пойдёт текст:** можно начать с `Ctrl+Alt+V` и остановить через `Ctrl+Alt+A` (или наоборот). Обработчик выбирает клавиша, которой вы *останавливаете* запись.

**Отмена, пока Claude думает или говорит:** нажатие любой горячей клавиши, пока ИИ отвечает или пока TTS зачитывает ответ, мгновенно всё отменяет и начинает новую запись. Контекст диалога сохраняется.

**Журнал Win+V:** расшифровка и ответ ИИ проходят через буфер обмена, поэтому журнал буфера обмена Windows (`Win+V`) показывает оба; это удобно, чтобы сравнить сказанное с ответом Claude.

### Параметры

```bash
# Выбрать другую модель Whisper
poetry run voice-mate --model medium

# Свои горячие клавиши
poetry run voice-mate --hotkey "ctrl+shift+r" --claude-chat-hotkey "ctrl+shift+c"

# Отключить режим Claude (только буфер обмена)
poetry run voice-mate --no-claude-chat

# Задать Claude системный промпт
poetry run voice-mate --claude-system-prompt "Ты краткий помощник по продуктивности."

# Ограничить многоходовой сеанс
poetry run voice-mate --claude-max-turns 20

# Отключить TTS (ответ попадает только в буфер обмена + сигнал)
poetry run voice-mate --no-tts

# Свой голосовой профиль TTS
poetry run voice-mate --tts-voice "Бразилец, низкий и неторопливый голос."

# Принудительно запускать TTS на CPU (медленнее, но работает без GPU)
poetry run voice-mate --tts-device cpu

# Сохранять созданное TTS аудио в папку
poetry run voice-mate --tts-save-dir ./tts_logs

# Принудительно расшифровывать Whisper на CPU (нет GPU)
poetry run voice-mate --cpu

# Переопределить определение GPU / бэкенд расшифровки для этого запуска
poetry run voice-mate --gpu-backend amd                       # принудительно AMD (ROCm)
poetry run voice-mate --gpu-backend nvidia --whisper-backend faster-whisper

# Использовать боковую кнопку мыши (только режим буфера обмена)
poetry run voice-mate --input-method mouse --mouse-button x

# Настроить сторожевой таймер и поддержку слушателя
poetry run voice-mate --listener-refresh-seconds 30 --watchdog-timeout 60
```

### Модели

| Модель             | Видеопамять | Скорость       | Качество      |
| ------------------ | ----------- | -------------- | ------------- |

| `base`             | ~140 МБ     | Быстро         | Хорошее       |
| `small`            | ~460 МБ     | Умеренно       | Очень хорошее |
| `medium`           | ~1.0 ГБ     | Умеренно       | Отличное      |

По умолчанию используется `large-v3-turbo`: лучший баланс скорости и качества, особенно для речи на нескольких языках.

## Приложение-компаньон (трей)

Компаньон представляет собой небольшое настольное приложение (PySide6), которое живёт в области уведомлений. Оно запускает движок и следит за ним, регистрирует горячие клавиши, воспроизводит звуковые сигналы, записывает каждую расшифровку в буфер обмена и проверяет, что она туда попала, а также собирает в одном месте состояние и кнопку выхода из всего. В Windows оно заменяет скрипт PowerShell/AutoHotkey и управляет движком внутри WSL2; в Linux это необязательный интерфейс. Сам движок не меняется: `make run` работает и без компаньона.

### Установка в Windows

**С помощью установщика (рекомендуется).** Запустите `VoiceMate-Setup-<версия>.exe`. Он устанавливает приложение только для вашего пользователя (без запроса прав администратора) в `%LOCALAPPDATA%\Programs\VoiceMate` и добавляет VoiceMate в меню «Пуск»; ярлык на рабочем столе и запуск при входе в систему необязательны (первая установка предлагает второе, дальше им управляет параметр **«Запускать VoiceMate при входе в систему»** в настройках). Установщик говорит на английском, португальском, испанском, русском и упрощённом китайском. Чтобы собрать его самостоятельно (Python 3.12+ и Inno Setup 6.3+, `winget install JRSoftware.InnoSetup`):

```powershell
make companion-venv        # один раз: .venv-companion с закреплёнными версиями PySide6 и PyInstaller
make companion-installer   # dist\VoiceMate (PyInstaller), затем dist\installer\VoiceMate-Setup-<version>.exe
```

**Из исходного кода.** С Python 3.12+ в Windows:

```powershell
make companion-venv   # один раз
make run-tray
```

В обоих случаях движок по-прежнему работает в WSL2 (установите его, как описано в [docs/wsl2.md](docs/wsl2.md)): компаньон запускает его сам или подключается к уже запущенному (например, к службе systemd). Если всё ещё запущен один из старых скриптов горячих клавиш (PowerShell или AutoHotkey), закройте его и удалите его ярлык из `shell:startup`: теперь `Ctrl+Alt+V` и `Ctrl+Alt+A` занимает компаньон.

### Закрепление на панели задач

Windows не позволяет установщикам закреплять приложения. Откройте меню «Пуск», найдите VoiceMate, щёлкните по нему правой кнопкой мыши и выберите **«Закрепить на панели задач»**. Щелчок по закреплённому значку, пока VoiceMate работает, открывает окно состояния; в меню правой кнопки есть **«Настройки»**, **«Перезапустить движок»**, **«Перезапустить WSL...»** и **«Выйти из VoiceMate»**. Закрепление использует ярлык из меню «Пуск», поэтому относится к установленному приложению. При первом запуске уведомление **«Закрепите VoiceMate на панели задач»** напоминает эти шаги.

Со значком в области уведомлений (микрофон, который показывает запись, расшифровку и готовность, как индикатор использования микрофона в Windows) дело обстоит иначе: Windows 11 прячет новые значки области уведомлений под стрелкой рядом с часами, поэтому VoiceMate по умолчанию держит свой значок на панели задач. Так происходит только до тех пор, пока никто не принял решение: если вы скроете значок в параметрах панели задач Windows, VoiceMate это учтёт и не вернёт его. Чтобы скрыть его насовсем, снимите флажок **«Всегда показывать значок VoiceMate на панели задач»** в разделе «Настройки» > **«Общие»**. Чтобы вернуть значок, скрытый в Windows, снимите этот флажок, нажмите **«Применить»**, снова установите его и нажмите **«ОК»**: значок снова появится, что бы ни было указано в параметрах Windows.

### Выход

Меню значка в области уведомлений > **«Выйти из VoiceMate»** (то же действие доступно кнопкой в окне состояния и пунктом в меню правой кнопки закреплённого значка). Выход останавливает движок, запущенный компаньоном; движок, к которому компаньон только подключился (например, служба systemd), продолжает работать. Из терминала, для установленного приложения (PowerShell):

```powershell
& "$env:LOCALAPPDATA\Programs\VoiceMate\VoiceMate.exe" --command quit
```

Из исходного кода: `make run-tray ARGS="--command quit"`. `--command` никогда не запускает VoiceMate: если он не запущен, ничего не происходит.

### Настройки

Меню значка в области уведомлений > **«Настройки...»**, три вкладки: **«Горячие клавиши»**; **«Звуки»** (встроенные звуки или ваши собственные файлы WAV, громкость); **«Общие»**: язык, уведомления, **«Запускать VoiceMate при входе в систему»**, **«Всегда показывать значок VoiceMate на панели задач»** (только в Windows) и движок (режим, дистрибутив WSL, папка движка и **«Перезапускать WSL при сбое звука»**: **«Автоматически»**, **«Сначала спрашивать»** или **«Никогда»**). Настройки сохраняются в `%APPDATA%\VoiceMate\companion.toml` (Linux: `~/.config/voicemate/companion.toml`) и остаются после удаления приложения. Журналы лежат в `%LOCALAPPDATA%\VoiceMate\logs` (Linux: `~/.local/state/voicemate/logs`); меню значка > **«Движок»** > **«Открыть журналы»** открывает их. Расшифровки, которые не попали в буфер обмена, хранятся в `%LOCALAPPDATA%\VoiceMate\pending.json` (Linux: `~/.local/state/voicemate/pending.json`), пока вы их не скопируете или не очистите список (**«Нескопированные»** > **«Очистить список»** в меню значка или **«Очистить»** в окне состояния), поэтому они остаются в списке **«Нескопированные»** после перезапуска или сбоя. Туда же сохраняются результаты, которые ещё ждали буфера обмена в момент выхода. Этот файл содержит текст расшифровок: он хранится в вашем профиле пользователя, удаляется, когда список становится пустым, и удаляется программой удаления вместе с журналами. Если его не удаётся прочитать, VoiceMate откладывает его как `pending.json.broken-<дата>`, начинает с пустым списком и сообщает об этом.

Новый язык вступает в силу после перезапуска, поэтому VoiceMate спрашивает **«Перезапустить VoiceMate?»**: **«Перезапустить сейчас»** перезапускает его (вместе с движком, около 10 секунд); **«Позже»** сохраняет выбор, а вкладка **«Общие»** до перезапуска показывает «Вступит в силу после перезапуска VoiceMate.».

### Linux (необязательно)

CLI работает как раньше. Для значка в трее и окна состояния выполните в репозитории:

```bash
poetry install --extras ui
make run-tray
```

В Linux движок сохраняет собственные горячие клавиши (вкладка **«Горячие клавиши»** показывает их только для чтения). Без системного трея (например, в GNOME без расширения AppIndicator) главным окном становится окно состояния. Чтобы добавить VoiceMate в меню приложений:

```bash
mkdir -p ~/.local/share/applications &&
  sed "s|@VOICEMATE_DIR@|$PWD|g" packaging/linux/voicemate-companion.desktop \
  > ~/.local/share/applications/voicemate-companion.desktop
```

### Устранение неполадок

| Симптом | Решение |
| ------- | ------- |
| Долго висит «Запуск движка...» | Первая загрузка модели занимает от 10 до 60 с. Посмотрите `engine.log` (**«Движок»** > **«Открыть журналы»**), а также дистрибутив WSL и папку движка в настройках |
| При первом запуске у горячей клавиши написано «Занято другим приложением» | Всё ещё работает старый скрипт горячих клавиш (PowerShell или AutoHotkey): закройте его и удалите из `shell:startup` |
| «Звук в WSL остановлен» или «Нет микрофона» | Подключите микрофон. WSL перезапускается в соответствии с параметром **«Перезапускать WSL при сбое звука»**; вручную: **«Движок»** > **«Перезапустить WSL...»** |
| «Движок старше этого приложения. Перезапустите или обновите его.» | Обновите копию репозитория в WSL (`git pull`), затем нажмите **«Перезапустить движок»** |
| Расшифровка не скопировалась | Она остаётся в списке **«Нескопированные»**, в меню значка (щёлкните, чтобы скопировать) и в окне состояния (**«Копировать»**), даже после перезапуска VoiceMate. **«Очистить список»** (меню значка) или **«Очистить»** (окно состояния) очищает его после подтверждения |
| SmartScreen предупреждает об установщике | Установщик не подписан: **«Подробнее»** > **«Выполнить в любом случае»** |

## Архитектура

```
app/
├── main.py                          # Точка входа + разбор CLI + подключение режимов
├── core/
│   └── config.py                    # Dataclass Config + FlowConfig + TTSConfig
└── services/
    ├── recorder.py                  # Захват микрофона (sounddevice)
    ├── transcriber.py               # Инференс Whisper (faster-whisper)
    ├── audio_feedback.py            # Кроссплатформенные звуковые сигналы
    ├── audio_player.py              # Аудиоплеер с очередью для потокового TTS
    ├── recording_session.py         # Конечный автомат: idle → recording → processing
    ├── transcription_handler.py     # Protocol + ClipboardHandler
    ├── claude_chat_handler.py       # Режим Claude: отправка + двойной буфер обмена + TTS + отмена
    ├── claude_runtime.py            # Мост sync ↔ asyncio для claude-agent-sdk
    ├── tts.py                       # Protocol TextToSpeech + NullSpeaker
    ├── voxcpm_speaker.py            # Озвучивание VoxCPM2 (потоковое + отмена)
    ├── input_listener.py            # Абстракция триггера клавиатуры / мыши
    ├── multi_hotkey_listener.py     # Несколько глобальных горячих клавиш с разными обработчиками
    ├── listener_keepalive.py        # Периодическая переустановка перехватчика (исправление для Windows)
    └── watchdog.py                  # Мониторинг состояния процесса
```

### Зачем нужна поддержка слушателя?

В Windows низкоуровневые перехватчики (`WH_KEYBOARD_LL` / `WH_MOUSE_LL`), которые используют библиотеки глобальных горячих клавиш, **молча снимаются** системой, если обработчик работает дольше `LowLevelHooksTimeout` (максимум 1000 мс в Windows 10+). При высокой нагрузке на CPU это происходит без всякого уведомления ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)). VoiceMate по умолчанию перерегистрирует горячую клавишу каждые 60 с, поэтому даже если система сняла перехватчик, следующий цикл установит его заново.

### Зачем сменный TTS?

Архитектура отделяет **оркестратор** (Protocol `TextToSpeech` в `tts.py`) от **конкретной реализации** (`VoxCPMSpeaker`). Так проще попробовать другие библиотеки TTS (edge-tts, ElevenLabs, Piper и т. д.): достаточно создать новую реализацию Protocol и подключить её через конфигурацию. Если библиотека не подошла, можно удалить только её файл.
