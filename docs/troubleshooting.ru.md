# Решение проблем

Назначение: как диагностировать проблемы VoiceMate, с точными сообщениями, которые показывает приложение, и действиями для каждого случая. Назад к [README](../README.ru.md).

## Первые шаги

1. **Прочитайте журналы.** Меню в области уведомлений > **Движок** > **Открыть журналы** открывает папку с `companion.log` и `engine.log` (в Windows `%LOCALAPPDATA%\VoiceMate\logs`, в Linux `~/.local/state/voicemate/logs`). В `engine.log` есть всё, что вывел движок.
2. **Выполните `make doctor`** в папке движка (для компаньона: внутри WSL). Он не останавливается на первой же проблеме: каждая проверка выводит ✓ или ✗, а после каждой неудачной проверки идёт строка `fix:` с командой, которую нужно выполнить.
3. **Перезапустите движок:** **Движок** > **Перезапустить движок**. Это также сбрасывает супервизор после «VoiceMate прекратил попытки».

### Что проверяет `make doctor`

В таком порядке: обнаруженная платформа; только в WSL2: сокет WSLg PulseAudio, `PULSE_SERVER`, плагин ALSA для PulseAudio, встроенные инструменты буфера обмена (`wl-copy`, `xclip`) и interop WSL для `clip.exe`; аудиобиблиотека, устройство ввода и устройство вывода; триггер горячих клавиш (доступ к `/dev/input` для `evdev`, `DISPLAY` для `pynput`, HTTP-демон в WSL2 или перехватчики Windows); исполняемый файл whisper.cpp, модель и VAD; устройство Vulkan (Linux и WSL2); Claude CLI (`node` и `claude`, пропускается, если сохранённый режим `clipboard`); `espeak-ng`, если установлен Kokoro; PyTorch с GPU.

## Сообщения компаньона

| Сообщение (заголовок уведомления) | Значение | Что делать |
|---|---|---|
| «VoiceMate запускается» | Горячую клавишу нажали, пока движок ещё загружает модель (от 10 до 60 секунд, а при самом первом запуске, когда скачивается модель, намного дольше) | Подождите и нажмите ещё раз |
| «Папка движка не найдена» | Ни в одной из папок, где ищет компаньон, нет копии движка | Клонируйте движок в одну из них ([installation.md](installation.md#2-install-the-engine)) или задайте «Папка движка:» в Настройки > **Общие** |
| «Не удалось запустить движок» | `wsl.exe` или `make run-engine` завершился с ошибкой | Посмотрите `engine.log`; проверьте, что `make` и `poetry` работают в login-оболочке (`wsl -e bash -lc "make --version && poetry --version"`) |
| «VoiceMate прекратил попытки» | Движок сбоил слишком часто (больше 5 перезапусков за 15 минут, 3 таймаута запуска подряд или больше 3 перезапусков WSL за 1 час) | Прочитайте `engine.log`, устраните причину, затем нажмите **Перезапустить движок**. При самом первом запуске медленная загрузка модели может три раза подряд израсходовать 240 секунд, отведённые на запуск движка: один раз выполните `make run` в папке движка (внутри WSL), остановите его через `Ctrl+C`, когда он загрузится, затем нажмите **Перезапустить движок** |
| «Движок устарел» / «Движок старше этого приложения. Перезапустите или обновите его.» | Копия движка старше компаньона | Обновите её (`git pull`, затем `make setup`), потом **Перезапустить движок** |
| «Движок запущен через systemd» | Движок запускает служба systemd `voicemate`, поэтому компаньон подключается к нему | Оставьте как есть или выполните в WSL `systemctl --user disable --now voicemate`, чтобы VoiceMate управлял движком сам |
| «Доступ к движку запрещён» | Движок отклонил токен API | VoiceMate перечитывает `~/.config/voicemate/api-token` каждые 30 секунд; если не проходит, перезапустите движок |
| «Движок недоступен» / «Движок занят» | Движок не ответил (вовремя) на нажатие горячей клавиши | VoiceMate продолжает переподключаться; если это длится долго, посмотрите `engine.log` |
| «Горячая клавиша недоступна» / «Занято другим приложением» (вкладка «Горячие клавиши») | Сочетание занято другой программой. Часто это старый скрипт горячих клавиш VoiceMate | Закройте скрипт и удалите его из `shell:startup` или выберите другие горячие клавиши |
| «Нет микрофона» | В Windows нет микрофона | Подключите его |
| «Микрофон недоступен» | Движку не удалось открыть микрофон | В Windows: разрешите классическим приложениям доступ к микрофону в параметрах конфиденциальности Windows и закройте приложения, которые используют его монопольно. Если завис звук WSL, перезапустите WSL |
| «Звук в WSL остановлен» | WSLg PulseAudio не отвечает | См. [Звук WSL и микрофон](#звук-wsl-и-микрофон) |
| «Ничего не распознано» / «Ничего не записано» | Речь не обнаружена или запись не содержит звука | Проверьте микрофон и уровень входного сигнала |
| «Медленная расшифровка» | Расшифровка идёт намного медленнее, чем длится звук, обычно когда нет GPU | `make doctor` (PyTorch с GPU, устройство Vulkan); см. [wsl2.md](wsl2.md#speech-to-text-performance-on-wsl2) |
| «Ошибка расшифровки» | Бэкенд распознавания речи вызвал ошибку | Прочитайте `engine.log` |
| «Claude не ответил» | Запрос к Claude не выполнен | Прочитайте `engine.log`; проверьте, что `claude` работает в WSL (`claude -p "ping"`) |
| «Не скопировано в буфер обмена» | Другое приложение держит буфер обмена заблокированным | Текст находится в списке **Нескопированные**: щёлкните его там, чтобы скопировать |
| «Ошибка копирования» | Не удалось скопировать из списка «Недавние» или «Нескопированные» | Повторите попытку |
| «Настройки сброшены» | Не удалось прочитать `companion.toml`; VoiceMate запустился с настройками по умолчанию и сохранил старый файл как `companion.toml.broken-<timestamp>` | Сравните и исправьте старый файл или оставьте настройки по умолчанию |
| «Список «Нескопированные» сброшен» | Не удалось прочитать `pending.json`; старый файл (с его текстами) сохранён как `pending.json.broken-<timestamp>` | Если нужно, восстановите тексты из старого файла |

## Режим распознавания

| Сообщение | Значение | Что делать |
|---|---|---|
| «Установить режим CPU?» / «Установить режим GPU?» | Выбранный вами режим не установлен в окружении движка | **Установить** скачивает его (размер указан в вопросе) и показывает вывод. «Отмена» оставляет текущий режим |
| «Установка не удалась. Подробности ниже; движок остаётся в текущем режиме.» | `make stt-install` завершился с ошибкой | Прочитайте вывод в окне, устраните причину (сеть, место на диске, ROCm), попробуйте снова или выполните `make stt-install MODE=gpu` в папке движка |
| «На этом компьютере нет режима GPU» | Проверка не нашла видеокарту, которую VoiceMate может использовать | Используйте режим CPU |
| «Режим GPU не работает. Установите его через меню «Распознавание».» (окно состояния) | Режим GPU перешёл на CPU | Меню в области уведомлений > «Распознавание» > «GPU (быстрее всего)» предлагает установку; `make doctor` показывает проверки GPU |
| «Смена режима распознавания уже идёт» | Проверка или установка ещё выполняется | Дождитесь её завершения и повторите попытку |
| «Не удалось сменить режим распознавания» | Движку не удалось перезапуститься с новым режимом | Прочитайте `engine.log` |

## Голосовой ассистент

| Симптом | Причина | Что делать |
|---|---|---|
| «Claude Code не найден», а голосовая просьба получает ответ «Не удалось запустить ассистента» | VoiceMate, запущенный при входе в систему, получает `PATH`, сохранённый в реестре Windows. Нативный установщик Claude Code кладёт `claude.exe` в `%USERPROFILE%\.local\bin`, и эту папку в `PATH` часто добавляет только профиль оболочки, поэтому терминал находит `claude`, а VoiceMate нет | В актуальной версии делать ничего не нужно: VoiceMate ищет ещё и в `~/.local/bin`, и в `%APPDATA%\npm`. Чтобы проверить, выполните в терминале `where claude`: если ничего не выводится, установите Claude Code. Если `claude` лежит в другом месте, задайте в `VOICEMATE_CLAUDE_CLI` полный путь к нему ([configuration.md](configuration.ru.md#переменные-окружения)), затем нажмите **Перезапустить** в окне ассистента |
| «Вход в Claude Code не выполнен» | На этом компьютере нет входа в Claude | Выполните в терминале `claude auth login`, затем **Перезапустить**. Вход в Claude Desktop не считается |
| «Не удалось запустить ассистента» или «Ассистент остановился» | Процесс завершился с ошибкой или закончился | Откройте `companion.log` (меню в области уведомлений > **Движок** > **Открыть журналы**), устраните причину, затем **Перезапустить** |
| «Не удалось подготовить ассистента» | VoiceMate не смог установить навык или записать `~/.voicemate/assistant.json` | Проверьте, что ваша пользовательская папка и `~/.claude` доступны для записи; подробности в журнале |
| Нет ссылки «Открыть на claude.ai», на телефоне ничего нет | Не удалось включить Remote Control. Ассистент продолжает работать на этом компьютере | Перезапустите разговор: Настройки > **Ассистент**, поставьте «Режим ассистента:» в положение «Выключено», примените, затем включите снова. `companion.log` говорит, что ответил запрос. Этот запрос не описан в документации и может меняться между версиями Claude Code (см. [исследование](research/claude-code-client.md#61-a-voicemate-owned-session-in-the-desktop-tested-works)) |
| Ассистент отвечает не на том языке или без имени | Навык не смог прочитать `~/.voicemate/assistant.json` и говорит «Настройки ассистента VoiceMate не найдены» | Перезапустите разговор (Настройки > **Ассистент**, выключить, применить, затем включить снова): VoiceMate записывает файл заново, когда разговор начинается. Проверьте, что файл лежит в вашей пользовательской папке (`~/.voicemate/`) |
| В меню в области уведомлений нет пункта «Ассистент» | Ассистент выключен | Настройки > **Ассистент** > «Режим ассистента:» > «Собственный разговор VoiceMate» |
| «Под ... подходит несколько разговоров» или «Ни один разговор не подходит под ...» | Набранная команда не смогла выбрать одно название | Наберите больше символов названия или отключите «Понимать голосовые команды в набранном тексте» |
| Файл личности отклонён | Это не существующий файл `.md` | Выберите файл Markdown кнопкой «Обзор...» |
| «Разговор Claude Desktop не выбран» | Выбран режим «Разговор Claude Desktop», а «Разговор в Desktop:» пусто | Введите в Настройки > **Ассистент** точное название с боковой панели Claude Desktop |
| «Не удалось подготовить ассистента» в режиме Desktop, а журнал говорит «no Claude Desktop conversation titled ...» | Ни у одного разговора Desktop с расшифровкой нет точно такого названия | Сверьте название по буквам с боковой панелью Claude Desktop; у разговора, в котором никогда не было сообщений, расшифровки ещё нет |
| «Не удалось запустить ассистента» в режиме Desktop, а журнал говорит `window_missing`, `conversation_missing` или `ambiguous` | Claude Desktop не открыт, разговора нет на его боковой панели или у двух разговоров одинаковое название | Откройте Claude Desktop, переименуйте один из двух одинаково названных разговоров, затем нажмите **Перезапустить** |
| Журнал говорит `locked` или `focus_lost`, и сообщение не дошло до Desktop | Экран был заблокирован или другое окно перехватило фокус, пока VoiceMate печатал. Ничего не было напечатано | Разблокируйте экран, не трогайте клавиатуру те 2 секунды, которые занимает сообщение, и отправьте его снова |
| Черновик, который вы набирали в разговоре Desktop, исчез | Сообщение от ассистента очищает черновик разговора, в который пишет | Не печатайте в разговоре, которым пользуется ассистент (режим Desktop), и в том, куда он вот-вот напишет |
| После обновления Claude Desktop режим Desktop перестаёт находить свои элементы управления | Обновление изменило окно, и профиль больше не подходит | Настройки > **Ассистент** > **Проверить сейчас**, чтобы найти новый профиль; если его нет, см. [desktop-profile.md](desktop-profile.md#writing-a-profile-for-a-new-desktop-version) |
| «Проблема: ...» в группе «Профиль Claude Desktop» | Импортированный или загруженный профиль отклонён (причина называет поле) | Исправьте файл и снова выберите **Импорт...** или нажмите **Использовать стандартный** |
| Ассистент не может открывать сайты, создавать pull request и пользоваться другими инструментами, которые есть только в Desktop | В «Собственном разговоре VoiceMate» у него есть только инструменты `voicemate` | Попросите его передать задачу разговору Desktop или переключитесь на режим Desktop |
| Ассистент молчит, а окно говорит «Голос недоступен» | Говорить нечем: движок остановлен или у него нет голоса (его движок голоса не Kokoro и не свой провайдер либо провайдер не работает), а у Windows нет голоса для этого языка, либо «Источник голоса:» стоит на «Голос движка» | В Настройки > **Ассистент** поставьте «Источник голоса:» на «Голоса Windows» (или «Автоматически») и нажмите **Проверить**; добавьте голос в Параметры Windows > Время и язык > Речь. Или проверьте Настройки > **Голос** и движок голоса в движке ([протокол](tts-provider-protocol.md#the-engine-speaks-the-same-protocol)); «Озвучивать ответы» должно быть включено. Ответы остаются доступными для чтения в окне |
| Голос ассистента замолкает, когда я записываю, и возвращается позже | Так задумано: голос никогда не говорит поверх микрофона. Он ждёт, пока вы записываете и пока запись расшифровывается, затем повторяет оборванную фразу и то, что стояло в очереди | Исправлять нечего. Новая просьба ассистенту, «stop talking» или горячая клавиша ассистента заглушают его насовсем |
| Кнопка **Говорить** в окне ассистента отключена | Ассистент не готов (выключен, запускается, отвечает или сломан) либо движок ещё расшифровывает последнюю запись | Дождитесь «Готов к работе» в окне. После ошибки нажмите **Перезапустить** |
| Ответ из другого разговора так и не пришёл | Отслеживаются только разговоры, в которые ассистент писал, которые он запускал или за которыми его просили наблюдать. Ожидание заканчивается через час без нового хода, наблюдение, о котором вы просили, через 12 часов, и ассистент получает заметку, когда заканчивается то или другое | Спросите у ассистента, что в ожидании. С «Просто сохранить» или «Только проиграть звук и сохранить ответ» ответ ждёт в **Ожидающие ответы**, а не в разговоре |
| Ассистент говорит, что не смог отправить в сессию терминала или IDE (центральный получил `not sent (in use)` или `not sent (busy)`) | `in use`: сессия открыта в программе или её расшифровка менялась в последние 2 минуты. `busy`: на последнее сообщение VoiceMate в неё ещё отвечают или ответили только что | Закройте сессию там или подождите, затем попросите снова. Подробнее в [assistant.md](assistant.ru.md#-решение-проблем) |
| У значка в области уведомлений синий бейдж | Ждут ответы из других разговоров | Выберите «Прослушать готовое» (меню в области уведомлений, `Ctrl+Alt+R`) или откройте окно |
| Горячая клавиша ассистента показывает «Занято другим приложением» | `Ctrl+Alt+S`, `Ctrl+Alt+W` или `Ctrl+Alt+R` занято | Настройки > **Горячие клавиши**: измените её или очистите |
| Ассистент отказывается менять настройку голосом | Её нет в каталоге (горячие клавиши, файлы, папки и движок в него не входят) или значение недопустимо | Измените её в Настройках. Список в [usage.md](usage.ru.md#меняйте-voicemate-голосом) |

## Звук WSL и микрофон

- Открытие микрофона никогда не блокирует горячую клавишу: оно выполняется в фоне. Если микрофон не открывается за 6 секунд, движок проигрывает сигнал ошибки, возвращается в режим ожидания и сообщает «Микрофон недоступен».
- В WSL2 движок каждые 20 секунд опрашивает WSLg PulseAudio (`pactl info`) и сообщает, что звук работает, не работает или неизвестен («Звук:» в окне состояния).
- Когда Windows теряет микрофон, WSLg PulseAudio часто зависает насовсем, даже после того как микрофон вернулся (`pactl info` выдаёт `Connection failure: Timeout`). Вернуть его может только `wsl --shutdown`.

Компаньон справляется с этим с помощью настройки «Перезапускать WSL при сбое звука:»:

| Настройка | Поведение |
|---|---|
| «Автоматически» (по умолчанию) | Перезапускает WSL сам, если не запущены другие дистрибутивы WSL: `wsl --shutdown` останавливает их все, включая Docker, поэтому в таком случае он сначала спрашивает |
| «Сначала спрашивать» | Показывает «Нужно перезапустить WSL» и пункт меню «Перезапустить WSL сейчас...» |
| «Никогда» | Ничего не делает; перезапускайте вручную через **Движок** > **Перезапустить WSL...** |

Перезапуск WSL нужен, когда звук не работает при двух проверках подряд или когда микрофон даёт сбой, а в Windows есть устройство записи и звук не работает. Он никогда не происходит, пока в Windows нет микрофона: компаньон ждёт его (проверяет каждые 3 секунды). Перед перезапуском он ждёт до 30 секунд, пока движок освободится, затем останавливает движок, выполняет `wsl --shutdown` и снова запускает движок.

Без компаньона: выполните `wsl --shutdown` в PowerShell, затем снова `make run`.

## Горячие клавиши

- **Windows с компаньоном:** компаньон регистрирует `Ctrl+Alt+V` и `Ctrl+Alt+A`. Если у сочетания указано «Занято другим приложением», им владеет другая программа.
- **Нативный движок в Windows (`make run`):** Windows может молча удалить низкоуровневый перехватчик клавиатуры, когда система сильно нагружена. Движок переустанавливает его каждые 60 секунд (`--listener-refresh-seconds`), а сторожевой таймер перезапускает зависший движок (`--watchdog-timeout`).
- **Wayland:** триггеру `evdev` нужно, чтобы ваш пользователь входил в группу `input` (`sudo usermod -aG input $USER`, затем войдите в систему заново).
- **X11:** триггеру `pynput` нужен `DISPLAY`.

## Проблемы движка

Сообщения движка, процитированные в этом руководстве, приведены на английском. Движок выводит их на языке `--output-lang`, по умолчанию это португальский (`pt-BR`), или на языке `VOICEMATE_LANG`, который важнее. Поэтому движок, запущенный простым `make run`, пишет журнал по-португальски: добавьте `ARGS="--output-lang en"` (или задайте `VOICEMATE_LANG=en` в оболочке, которая его запускает), чтобы читать английский текст. Компаньон передаёт этот флаг сам, исходя из «Язык диктовки:» в Настройках.

| Симптом | Причина | Решение |
|---|---|---|
| «Could not open the HTTP API on 127.0.0.1:{port}» в журнале движка | Порт занят, часто другим движком | Остановите другой движок или выберите другой порт (`--daemon-port`, а также `daemon_port` в `companion.toml`) |
| «Claude flow disabled: extra 'claude' not installed.» | Не хватает extra `claude` | `poetry install --extras claude` или `make configure` |
| «Failed to start Claude (run `claude login`)» | Claude CLI отсутствует или вход выполнен не в учётную запись | Установите его и войдите ([installation.md](installation.md#claude-code-cli-for-the-claude-flow)) |
| «TTS disabled: engine '{engine}' packages not installed.» | Не хватает extra движка TTS | Установите extra, названный в следующей строке журнала, или запустите с `--no-tts` |
| Английская речь расшифровывается неправильно (как будто она португальская) | Движок, запущенный вручную, по умолчанию закрепляет Whisper на португальском | `make run ARGS="--output-lang en"` или `--transcription-language en`. С компаньоном задайте «Язык диктовки:» в Настройки > **Общие** |
| Расшифровка в 10-50 раз медленнее ожидаемого | Бэкенд перешёл на CPU | `make doctor` (PyTorch с GPU); на AMD `rocminfo` должен показывать GPU |
| Не удалась сборка CTranslate2-ROCm | Неполные пакеты разработки ROCm или (ROCm 7) сборка, выбравшая gcc: «language hip not recognized» | `make doctor`; установите ROCm HIP SDK; `git pull` и `make configure` пробуют снова, теперь с clang из ROCm. См. [wsl2.md](wsl2.md#ctranslate2-rocm-faster-whisper-on-the-gpu-optional-best-quality) |
| «Conv1D on GPU currently requires the cuDNN library» в журнале движка, а расшифровка на GPU AMD не удаётся | CTranslate2-ROCm, собранный без MIOpen (аналога cuDNN у AMD), на ROCm 7 | `git pull`, затем `make configure` и снова согласитесь на сборку CTranslate2-ROCm: теперь сборка включает MIOpen. До тех пор движок переходит на openai-whisper (`ct2_rocm_ok = false`) |
| Язык интерфейса не тот, который вы выбрали | Язык меняется после перезапуска | Ответьте «Перезапустить сейчас» на вопрос «Перезапустить VoiceMate?» |

## Старые скрипты горячих клавиш (без компаньона)

Скрипт PowerShell `scripts/windows/voicemate-hotkeys.ps1` выводит «daemon offline», когда на порту никто не отвечает: запустите движок в WSL командой `make run`, затем снова нажмите горячую клавишу. Эти скрипты работают только с движком, запущенным без токена (`make run`), и никогда с `make run-engine`.
