# VoiceMate 0.4.0: release notes

VoiceMate 0.4.0 starts your custom voice provider for you: give it the command once and the voice is there after every reboot. The engine's own voice now waits while it loads instead of losing sentences, and a provider that was down when the engine started no longer leaves the engine mute.

## Highlights

- **Your voice provider starts with VoiceMate:** in Settings > **Voice**, **Start command:** takes the command line that starts your custom voice provider (for example `bash ~/my-voice-provider/start.sh`). VoiceMate orchestrates the start: the engine runs the command whenever nothing listens at the provider's address, when the engine starts and again if the provider goes down, at most once a minute and never while the last process it started is still running. A provider that is only slow to answer is not started again. The command runs through the shell on the engine's side (inside WSL when the engine runs there), without the engine's virtual environment and GPU tuning, and detached from it. VoiceMate never stops the provider, so its models stay loaded when the engine restarts. The command is not written to the log and must be a single line. Details: [docs/tts-provider-protocol.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/tts-provider-protocol.md#starting-the-provider-with-voicemate).
- **A voice that waits while it loads:** with **Voice source:** set to **The engine's voice**, a sentence that finds the engine still loading its voice now waits for it (up to 90 seconds, trying every 5, once per outage) instead of being lost, and the short notices no longer fall to the voices of Windows: they stay on screen. **Automatic** works as before where Windows has a voice.
- **No more mute engine after a late provider:** a custom voice provider that was down when the engine started no longer turned the engine's voice off until the engine was restarted. Now the engine's voice comes back on its own when the provider does: with a start command it waits for it, and without one it says the provider is down.

## Requirements

- As in 0.1.0: Windows 11, or Windows 10 build 19044 or newer, 64-bit, with WSL2 and WSLg, and the engine set up from source inside WSL ([docs/wsl2.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/wsl2.md)).
- For the voice assistant: the Claude Code CLI on Windows (the `claude` command), signed in once with `claude auth login`. For the Desktop mode, Claude Desktop open with the screen unlocked.

## Upgrading from 0.3.0

1. Update the engine inside WSL, in the folder where you cloned VoiceMate:

   ```bash
   cd ~/voice-mate
   git pull
   make setup    # installs the new dependencies; your earlier answers are the defaults
   make doctor
   ```

2. Download and check the installer (step 2 below), then run it. If VoiceMate is running, the installer first asks "VoiceMate is running. Setup will close it, and the engine it started, before installing. Continue?"; confirm, and it closes VoiceMate together with its engine, then installs in place. Your settings, hotkeys and the **Not copied** list are kept. The box "Automatically start VoiceMate" is offered on the first install only, so it does not appear again.

3. Optional: if your custom voice provider has a command that starts it, enter it in **Settings...** > **Voice** > **Start command:** ([how it works](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/tts-provider-protocol.md#starting-the-provider-with-voicemate)). Nothing else changes, and your settings are kept.

## How to install (first time)

The installer contains the tray app. The speech engine runs inside WSL2 and is set up once from source; the tray app then starts it for you.

The same steps, with a screenshot of every installer page, are in the [installation guide](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/install-guide.md).

### 1. Set up the engine in WSL2 (once)

1. In Windows, update WSL: `wsl --update`. WSLg, which gives WSL access to your microphone, comes with it.
2. With an AMD GPU: install the AMD Adrenalin driver 26.2.2 or newer in Windows, then ROCm for WSL (track 7.2) inside Ubuntu, following [AMD's guide](https://rocm.docs.amd.com/projects/radeon/en/latest/docs/install/wsl/install-radeon.html). `rocminfo` must list your GPU.
3. Inside Ubuntu, install the audio and build packages:

   ```bash
   sudo apt install -y libportaudio2 libasound2-plugins pulseaudio-utils wl-clipboard \
                       git cmake build-essential libvulkan-dev glslc vulkan-tools \
                       spirv-headers spirv-tools glslang-tools espeak-ng
   ```

4. Make sure Python 3.12 and [Poetry](https://python-poetry.org/docs/#installation) are installed, then clone VoiceMate into your home folder and run the setup:

   ```bash
   git clone https://github.com/nano-br/voice-mate.git ~/voice-mate
   cd ~/voice-mate
   make setup    # detects WSL2 and the GPU, installs the matching PyTorch and the modules you pick
   make doctor   # checks microphone, audio, GPU and binaries, with a fix for each problem
   ```

   `make setup` asks for the default transcription mode (CPU or GPU); you can switch later from the tray menu. It may also offer a systemd service that starts the engine with WSL. You do not need it with the tray app.

More detail and troubleshooting: [docs/wsl2.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/wsl2.md).

### 2. Download and check the installer

Download `VoiceMate-Setup-0.4.0.exe` and its `.sha256` file from the release page. In PowerShell, in the download folder:

```powershell
(Get-FileHash .\VoiceMate-Setup-0.4.0.exe -Algorithm SHA256).Hash
```

The value must match the one in the `.sha256` file (upper or lower case does not matter). If it does not, do not run the file and download it again.

### 3. Run the installer

1. Open `VoiceMate-Setup-0.4.0.exe`. The installer is not code-signed, so Windows SmartScreen may warn on first run: choose **More info**, then **Run anyway**.
2. The installer starts in your Windows display language when it is one of the five; otherwise it shows a language dialog, in English. VoiceMate installs for your user only, without an administrator prompt, into `%LOCALAPPDATA%\Programs\VoiceMate`, and adds itself to the Start menu.
3. Optionally create a desktop shortcut and let VoiceMate start when you sign in, then finish and launch VoiceMate.

### 4. First run

1. The VoiceMate icon appears in the tray. While the engine loads the model (10 to 60 seconds), VoiceMate shows "Starting engine...".
2. If it shows "Engine folder not found", open **Settings...** > **General** and set **WSL distro** and **Engine folder**.
3. Try dictation: press `Ctrl+Alt+V`, speak, press `Ctrl+Alt+V` again, and paste with `Ctrl+V`.
4. If the microphone does not work, open Windows **Settings** > **Privacy & security** > **Microphone** (**Privacy** on Windows 10) and allow desktop apps to use it. If audio stays stuck, use the tray menu > **Engine** > **Restart WSL...**, or run `wsl --shutdown`.

### 5. Turn on the voice assistant (optional)

1. Install the [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) on Windows and run `claude auth login` once in a terminal.
2. Press the **Assistant** button in the status window (or `Ctrl+Alt+W`). While the assistant is off, its window says how to turn it on.
3. In **Settings...** > **Assistant**, choose the **Assistant mode:**. For **A Claude Desktop conversation**, type the exact title of that conversation in **Desktop conversation:**.
4. Press `Ctrl+Alt+S`, ask "what are my conversations doing?", and press `Ctrl+Alt+S` again.

The assistant needs no voice set up: with no voice engine, it speaks with the voices of Windows (Settings > **Assistant** > **Voice source:** is **Automatic**). To talk without the hotkey, click **Talk** in the assistant window; it becomes **Stop and send** while it records.

The whole flow, with diagrams: [docs/usage.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/usage.md#voice-assistant).

### 6. Pin to the taskbar

Windows does not let installers pin apps. Open Start, search for VoiceMate, right-click it and choose **Pin to taskbar**.

## Known limitations

- The Desktop mode of the voice assistant types into Claude Desktop through Windows UI Automation: it takes the keyboard for about 2 seconds and clears any draft in that conversation's prompt.
- Conversations the assistant starts with **Full access, never ask (risky)** can change any file and run any command without asking. Keep the default unless you trust what you ask them to do.
- The installer is not code-signed, so SmartScreen warns on first run (see step 3).
- AMD support is validated on a single card (Radeon RX 9070 XT) under WSL2, with ROCm 7.2.
- When Windows loses its microphone, WSLg audio can hang until WSL restarts. The tray app can restart WSL for you, following **Restart WSL when audio fails**.
