VoiceMate 0.5.1 is a round of fixes for the voice assistant and for long dictation: a message for a Claude Desktop conversation that was pasted but not sent is typed again, a reply always reaches you by voice, a new conversation is no longer refused when four are open, the assistant window keeps its messages, and a long recording goes to your own transcription service in parts.

## Highlights

- **Messages to Claude Desktop are not lost:** when a message was pasted but not sent (the focus moved while VoiceMate was typing), VoiceMate types it again, up to three times, and checks that the prompt box is empty after Enter. A message that was sent is never typed twice.

- **Every reply is spoken:** a reply that comes outside the assistant's reply model is read aloud (the start of its text, without Markdown marks, code or links) instead of only shown, and what it asked VoiceMate to do is carried out.

- **A new conversation when four are open:** VoiceMate parks the idle conversation unused the longest and starts the new one; the next message to the parked one resumes it with its whole history. When all four are busy, the assistant sends your request to one of them instead of stopping.

- **The assistant window keeps its messages** when the assistant's conversation summarizes its context. It used to be emptied, which looked like a restart.

- **Voice while the engine loads:** a spoken line waits up to 4 minutes for an engine that is still loading (it was 90 seconds) instead of being lost.

- **Long dictation with your own transcription service:** a recording longer than the service's `max_seconds` is cut at the quietest moment near the limit and sent in parts, instead of going to the built-in engine. A service that answers `busy` is asked again for a few seconds first. Details: [docs/stt-provider-protocol.md](https://github.com/nano-br/voice-mate/blob/v0.5.1/docs/stt-provider-protocol.md).

## Download

- **`VoiceMate-Setup-0.5.1.exe`**: the Windows tray app. Per-user install into `%LOCALAPPDATA%\Programs\VoiceMate`; it replaces 0.5.0 in place and keeps your settings. The `.sha256` file next to it holds its SHA-256 checksum.
- The installer contains the tray app only. The speech engine runs inside WSL2 and is set up from source; if you already have it, update it as described in the release notes files (`git pull`, then `make setup`).

## Requirements

- As in 0.1.0: Windows 11, or Windows 10 build 19044 or newer, 64-bit, with WSL2 and WSLg, and the engine set up from source inside WSL ([docs/wsl2.md](https://github.com/nano-br/voice-mate/blob/v0.5.1/docs/wsl2.md)).
- For the voice assistant: the Claude Code CLI on Windows (the `claude` command), signed in once with `claude auth login`. For the Desktop mode, Claude Desktop open with the screen unlocked.

## Known limitations

- The Desktop mode of the voice assistant types into Claude Desktop through Windows UI Automation: it takes the keyboard for about 2 seconds and clears any draft in that conversation's prompt.
- Conversations the assistant starts with **Full access, never ask (risky)** can change any file and run any command without asking. Keep the default unless you trust what you ask them to do.
- The installer is not code-signed, so SmartScreen warns on first run: choose **More info**, then **Run anyway**.
- AMD support is validated on a single card (Radeon RX 9070 XT) under WSL2, with ROCm 7.2.
- When Windows loses its microphone, WSLg audio can hang until WSL restarts. The tray app can restart WSL for you, following **Restart WSL when audio fails**.
