VoiceMate 0.4.0 starts your custom voice provider for you: give it the command once and the voice is there after every reboot. The engine's own voice now waits while it loads instead of losing sentences, and a provider that was down when the engine started no longer leaves the engine mute.

## Highlights

- **Your voice provider starts with VoiceMate:** in Settings > **Voice**, **Start command:** takes the command line that starts your custom voice provider (for example `bash ~/my-voice-provider/start.sh`). VoiceMate orchestrates the start: the engine runs the command whenever nothing listens at the provider's address, when the engine starts and again if the provider goes down, at most once a minute and never while the last process it started is still running. A provider that is only slow to answer is not started again. The command runs through the shell on the engine's side (inside WSL when the engine runs there), without the engine's virtual environment and detached from it. VoiceMate never stops the provider, so its models stay loaded when the engine restarts. The command is not written to the log and must be a single line. Details: [docs/tts-provider-protocol.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/tts-provider-protocol.md#starting-the-provider-with-voicemate).
- **A voice that waits while it loads:** with **Voice source:** set to **The engine's voice**, a sentence that finds the engine still loading its voice now waits for it (up to 90 seconds, trying every 5, once per outage) instead of being lost, and the short notices no longer fall to the voices of Windows: they stay on screen. **Automatic** works as before where Windows has a voice.
- **No more mute engine after a late provider:** a custom voice provider that was down when the engine started no longer turned the engine's voice off until the engine was restarted. Now the engine waits for it.

## Download

- **`VoiceMate-Setup-0.4.0.exe`**: the Windows tray app. Per-user install into `%LOCALAPPDATA%\Programs\VoiceMate`; it replaces 0.3.0 in place and keeps your settings. The `.sha256` file next to it holds its SHA-256 checksum.
- The installer contains the tray app only. The speech engine runs inside WSL2 and is set up from source; if you already have it, update it as described in the release notes files (`git pull`, then `make setup`).

## Requirements

- As in 0.1.0: Windows 11, or Windows 10 build 19044 or newer, 64-bit, with WSL2 and WSLg, and the engine set up from source inside WSL ([docs/wsl2.md](https://github.com/nano-br/voice-mate/blob/v0.4.0/docs/wsl2.md)).
- For the voice assistant: the Claude Code CLI on Windows (the `claude` command), signed in once with `claude auth login`. For the Desktop mode, Claude Desktop open with the screen unlocked.

## Known limitations

- The Desktop mode of the voice assistant types into Claude Desktop through Windows UI Automation: it takes the keyboard for about 2 seconds and clears any draft in that conversation's prompt.
- Conversations the assistant starts with **Full access, never ask (risky)** can change any file and run any command without asking. Keep the default unless you trust what you ask them to do.
- The installer is not code-signed, so SmartScreen warns on first run: choose **More info**, then **Run anyway**.
- AMD support is validated on a single card (Radeon RX 9070 XT) under WSL2, with ROCm 7.2.
- When Windows loses its microphone, WSLg audio can hang until WSL restarts. The tray app can restart WSL for you, following **Restart WSL when audio fails**.
